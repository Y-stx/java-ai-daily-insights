## 四、AI 应用工程师每日小任务

- 用 `Spring AI` 或 `LangChain4j` 写一个最小 Chat API demo，并把模型 `endpoint`、`api key`、`model name` 放进配置文件，验证同一接口可切换不同模型供应商。
- 把一个现有内部查询接口整理成 MCP server 设计草案，明确工具名、JSON 入参、返回结构、鉴权方式、超时与审计策略。
- 选一组业务文档做最小 RAG 实验，完成文档切分、Embedding 字段设计、向量库元数据设计，并记录召回失败的 3 个典型样例。
- 在模型调用链路上补一层日志观测，至少记录请求耗时、模型名、提示词模板版本、召回文档数量和失败原因，便于后续做质量排查。
- 给 AI 接口增加一版基础限流与权限治理方案，区分普通问答、敏感工具调用、知识库写入三类权限，并定义对应限流阈值与审计要求。

## 五、对 Java 开发者的实际启发

- Java 生态的主线已经很清晰：`Spring AI`、`LangChain4j`、`spring-ai-alibaba`、`modelcontextprotocol/java-sdk` 分别覆盖应用抽象、快速开发、国内模型接入和 MCP 协议接入，已经足够支撑企业级 PoC 到平台化演进。
- MCP 值得优先关注。`OpenAI Developers` 出现 `Docs MCP`，同时 GitHub 侧有 `modelcontextprotocol/java-sdk` 与 `agent-client-protocol/agent-client-protocol` 这类协议项目，说明“模型如何标准化调用工具与外部系统”正在成为工程重点。
- RAG 不能只靠更大上下文窗口。背景新闻里提到 “Larger Context Windows Don’t Fix RAG”，对 Java 团队的直接启发是：要把精力放在文档切分、检索策略、元数据过滤、重排和观测闭环上，而不是只扩大 prompt。
- 幻觉与合规风险需要前置治理。`KPMG pulls report on AI usage due to apparent hallucinations` 这类事件提醒后端团队：模型输出必须纳入可追踪链路，至少保留来源文档、工具调用记录和人工审核开关。
- 招聘与项目趋势共同指向“AI 工程化”而非单点模型调用。对 Java 开发者最有价值的能力组合是：Spring Boot 服务化、模型网关封装、RAG 数据管道、工具调用协议化、日志审计与权限治理。
