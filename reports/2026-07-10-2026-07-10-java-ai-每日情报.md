## 四、AI 应用工程师每日小任务

1. 给一个 RAG demo 增加引用来源返回，接口输出结构至少包含 `answer`、`source_title`、`source_url` 和 `chunk_id`，并在前端或日志中能追踪到原始文档片段。
2. 为一次模型调用增加超时、重试、错误分类和 fallback 文案，区分网络错误、限流错误、模型服务异常和内容为空四类失败原因。
3. 设计一个工具调用白名单，只允许模型调用 2-3 个只读业务接口，明确每个工具的入参、返回字段、权限边界和审计日志字段。
4. 对比 LangChain4j 与 Spring AI 的 `ChatModel`、`EmbeddingModel`、`VectorStore` 抽象差异，写出 5 条结论，并说明各自更适合的项目类型。
5. 为模型网关补一组基础观测指标，包括请求量、成功率、平均耗时、P95 耗时、限流次数、fallback 次数和按模型维度的错误分布。

## 五、对 Java 开发者的实际启发

Java AI 应用开发正在从“直接调模型接口”转向“平台化工程能力”：模型接入、RAG、工具调用、MCP、权限治理、日志观测和限流熔断会成为后端开发者的日常能力。

Spring AI、LangChain4j、spring-ai-alibaba 和 MCP Java SDK 值得持续跟踪。它们分别对应 Spring 生态集成、Java 原生 LLM 应用开发、国内模型服务适配，以及模型工具协议接入，基本覆盖了企业 Java 团队落地 AI 应用的主要路径。

招聘方向显示，大厂更关注 AI 工程化和平台能力，而不只是 Prompt 编写。Java 开发者应把已有后端能力迁移到 AI 场景中，例如网关、鉴权、审计、异步任务、缓存、向量检索、灰度发布和可观测性。

从 OpenAI Developers 数据看，Docs MCP、Codex plugin、Realtime/audio 等方向仍有工程参考价值。对 Java 团队来说，短期更实际的切入点是 MCP 工具服务、文档知识库问答、模型调用治理和内部研发助手，而不是一次性追求复杂 Agent。
